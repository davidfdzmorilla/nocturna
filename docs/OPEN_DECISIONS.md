### Nota de T43/T60: asimetría entre `max_editor_calls_per_night` e `editor_reserve_tokens`

`max_editor_calls_per_night = 2` (default) permite **dos intentos** (incluso si el primero retorna JSON inválido). La reserva `editor_reserve_tokens = 60.000` cubre **una llamada** completa. Con cfg-2026-09-18: peor caso de un intento es 2.500 + 40×850 = 36.500 tokens. Peor caso de dos intentos: 36.500 × 2 = 73.000 > 60.000. El segundo intento se deniega gracefully (no hay sobregasto), pero de facto el reintento por JSON inválido no existe (se necesitaría 73.000 en reserva, tenemos 60.000). Opciones: (a) mantener y documentar la asimetría (reserva ≈ 1 llamada); (b) cambiar `max_editor_calls_per_night = 1` a la realidad de la reserva; (c) aumentar reserva a 73.000+ si el reintento es crítico. **Asignado a T60 análisis:** si T60 ve alta tasa de JSON inválido del Editor, reabrir; si es raro, mantener asimetría documentada.
